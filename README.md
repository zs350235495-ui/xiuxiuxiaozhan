## 🚀 现代网络协议与客户端流量调度机制 (Client Architecture)

不同操作系统平台对底层网络数据包的处理机制存在本质差异，理解其工作模型是实现稳定、低延迟网络连接的基础：

### 1. TUN 虚拟网卡 vs 系统系统代理 (System Proxy)
* **系统代理模式 (HTTP/SOCKS5)**：
  * **机制**：仅拦截主动声明支持系统代理解析的应用程序（如主流浏览器、邮件客户端）。
  * **局限**：命令行终端工具（如 `curl`、`git`、`ssh`）及大量无代理设置界面的应用程序会直接绕过代理直连公网，容易引发网络阻断。
* **TUN 虚拟网卡接管模式**：
  * **机制**：在系统网络层注入一个虚拟网络接口（TUN Device），配合本地路由表策略将操作系统的全部 IP 数据报文接管至用户态转发引擎。
  * **优势**：实现真正的全系统全局接管，无需针对单个软件繁琐配置代理端口，杜绝流量泄露。

### 2. DNS 污染防护与分流匹配流水线
```text
[应用发起网络请求]
        │
        ▼
┌─────────────────┐      命中规则
│  内置规则引擎匹配 ├──────────────────► [直连出站 (Direct)]
└───────┬─────────┘
        │ 未命中 / 走远程代理
        ▼
┌─────────────────┐      即时分配
│ Fake-IP 虚拟地址池 ├──────────────────► [建立虚拟 TCP 握手 (RTT ≈ 0)]
└───────┬─────────┘
        │
        ▼
┌─────────────────┐
│ 远端专线出口解析 ├──────────────────► [目标服务器建立真实握手与数据传输]
└─────────────────┘
```

## 💻 跨平台主流客户端零门槛接入指南

针对不同操作系统平台，本知识库总结了主流开源客户端的最佳实践配置策略：

### 1. 桌面平台 (Windows / macOS / Linux)
* **流量模式选择**：
  * 日常网页浏览建议使用 **规则分流模式 (Rule Mode)**，配合本地 PAC 或内置规则库实现境内直连、境外加速；
  * 开发者环境、Git 同步、Docker 镜像拉取或终端命令行场景，强烈建议开启 **TUN 虚拟网卡模式**，实现操作系统底层全流量接管。
* **内存与性能优化**：
  * 调高系统文件描述符上限（`ulimit -n 65535`），避免高并发连接时句柄耗尽；
  * 启用硬件加速 AES-NI / AVX2 指令集加速协议加解密，降低 CPU 占用率。

### 2. 移动平台 (iOS / Android)
* **省电与网络切换优化**：
  * 启用客户端底层 Keep-Alive 保活机制，避免从 Wi-Fi 切换至蜂窝网络（4G/5G）时发生 TCP 链接重连雪崩；
  * 配置合理的 DNS 缓存 TTL，减少移动网络环境下的频繁 DNS 递归查询功耗。

## 🛠️ 零门槛网络链路排障与自愈决策树

在日常使用中，如遇连接异常或网页加载失败，可参考以下标准化排障决策模型快速定位：

```text
[网络连接异常 / 网页无法打开]
        │
        ▼
┌───────────────────────┐
│ 检查本地代理核心运行状态 │
└───────────┬───────────┘
            │
      ┌─────┴─────┐
      ▼           ▼
  [核心异常]    [核心正常]
      │           │
  重启内核/服务    ▼
            ┌───────────────────────┐
            │ 节点延迟测试 (URL-Test) │
            └───────────┬───────────┘
                        │
                  ┌─────┴─────┐
                  ▼           ▼
             [全部超时]    [单节点正常]
                  │           │
            检查本地时间同步   ▼
            或更新节点订阅  ┌───────────────────────┐
                            │ 检查系统代理 / TUN 状态 │
                            └───────────┬───────────┘
                                        │
                                  ┌─────┴─────┐
                                  ▼           ▼
                             [未接管流量]   [已正常接管]
                                  │           │
                              开启 TUN 模式   ▼
                                        排查 DNS 泄露
                                        与规则冲突
```

### 常见故障速查表
1. **全部节点 Ping 延迟显示超时/断连**：
   * **常见原因**：本地系统时间与国际标准时间偏差超过 90 秒，导致 TLS 证书或时间戳握手校验失败；
   * **自愈方案**：前往操作系统时间设置，开启“自动同步网络时间 (NTP)”。
2. **浏览器无法打开网页，但即时通讯软件正常**：
   * **常见原因**：本地 DNS 解析污染或系统代理端口被其他残留进程占用；
   * **自愈方案**：切换至 TUN 模式接管系统网络，或清除本地 DNS 缓存（Windows 执行 `ipconfig /flushdns`，macOS 执行 `sudo dscacheutil -flushcache`）。
3. **部分特定站点加载缓慢或无法识别地域**：
   * **常见原因**：分流规则未收录该站点域名，触发了默认路由 (MATCH / FINAL)；
   * **自愈方案**：在客户端规则配置中将该域名添加至代理策略组，或切换为全局代理测试。
